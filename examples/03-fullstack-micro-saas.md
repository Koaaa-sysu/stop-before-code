# 实战案例 3：轻量 Web 工具（SVG 图标调色板）

> **场景**：开发者向 AI 提出：“我想做一个 Web 工具，能把上传的 SVG 图标批量修改颜色并一键下载。”

---

## 传统 AI Coding 的惨痛对局（Without SBC）
1. AI 习惯性地启动全栈方案：Next.js + Prisma + PostgreSQL + AWS S3 上传。
2. 配置了文件上传接口、后端文件写入、存储桶凭证环境配置。
3. 开发者只是想给几个本地图标改个色，结果为了跑通这个项目，必须先在本地配置 Docker 和 PostgreSQL，甚至还要填 S3 的 Access Key。
4. 典型的“杀鸡用牛刀”，过度工程化导致弃坑。

---

## Stop Before Code 的防冲动实战（With SBC）

### Phase 1: Working Backwards
> 🛑 **【代码门禁生效中 · 请先定型】**  
> **逆向产品宣言**：这是一个纯客户端单页（Client-Side SPA）Web 工具，让 UI 设计师与开发者直接将 SVG 拖入浏览器，在内存中即时拾色预览，并一键打包为 Zip 下载，隐私数据永不离开本地浏览器。

### Phase 2: Socratic 3-Shaping
> 1. **胃口与形态（Appetite）**：
>    - A. [强烈推荐] 纯客户端单 HTML 文件（包含 Alpine.js/Vue CDN + JSZip，无需后端，无需 Node 环境，双击即可在浏览器运行，甚至能直接部署到 GitHub Pages）
>    - B. Next.js 全栈服务端方案
> 2. **暴力减法（Anti-Scope）**：
>    - 建议砍掉：**坚决不写任何后端 API、不搭数据库、不做文件上传服务器**！利用现代浏览器的 `FileReader` 和 `Blob API` 在内存中完成所有操作，零服务器成本，零隐私泄露风险。
> 3. **兔子洞与容错体验（Edge & Rabbit Hole）**：
>    - **兔子洞预警**：有些复杂 SVG 包含内嵌 CSS 或渐变标签（`<linearGradient>`），直接字符串替换 `fill` 可能会破坏渐变。需要明确本期仅支持处理基础 Path 的单色着色。
>    - **极值容错**：一次性拖入 50 个 SVG 时，浏览器不能卡死，界面需展示批量转换进度条。
