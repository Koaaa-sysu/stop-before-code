# Methodology · Stop Before Code 的顶层产品哲学

> **"The easiest way to avoid writing bad code is to avoid building the wrong thing."**

在前沿推理引擎与自主编程智能体（GPT-6.1、CloudOps 5.5、Claude 4.5、Gemini 3 Ultra 等）吞吐达每秒数万 Token 的时代，代码不再是稀缺资产。相反，**未经审慎思考、高速堆叠的代码是极其高昂的技术负债与维护灾难**。

`Stop Before Code (SBC)` 不是一个随意的提示词技巧，它的底层深度扎根于三大学派的产品工程圣经：

---

## 1. Basecamp《Shape Up》：构建之前先定型 (Shaping)

传统敏捷往往陷入“故事点（Story Points）与无限迭代”的泥潭，而 AI 时代更是将这种混沌放大了百倍——开发者给出一句模糊的指示，AI 立即写出上千行冗余代码。

SBC 借鉴了 Ryan Singer 在 Basecamp 总结的 **Shape Up** 核心框架：

### 核心 1：Appetite（胃口）替代 Estimation（工期估算）
- **传统程序员思维**：“做这个功能需要多长时间？”
- **SBC 产品经理思维**：“**你愿意为这个问题投入多大成本（Appetite）？**”
- 如果用户的心理预期是一个 30 分钟搞定的极简小功能（Small Batch），AI 绝不应该去引入复杂的企业级状态管理、ORM、微服务架构。胃口决定了复杂度的天花板。

### 核心 2：Rabbit Holes（兔子洞与时间黑洞）
- 在任何项目中，总有 20% 的隐形细节会吞噬 80% 的时间（例如自建复杂的 OAuth 鉴权、试图兼容各种奇葩的跨浏览器样式、过早优化的分布式并发）。
- SBC 在动工前强制要求 AI **肉眼识别并指出“兔子洞”**，在 Spec 中明确声明“本期坚决绕开（No-Gos）”。

### 核心 3：Fat-Marker Sketches（粗笔草图）
- 在还没想清楚产品骨架前，不要陷入细枝末节。像用一支粗马克笔在餐巾纸上画图一样，只关注核心元素（Affordances）与连接线。
- SBC 的 **ASCII 原型草图** 正是粗笔草图在终端环境中的数字再现。

## 2. Marty Cagan《Inspired》：杀死价值风险 (Value Risk)

硅谷产品大师 Marty Cagan 在《启示录（Inspired）》中总结了软件开发面临的四大核心风险：
1. **价值风险（Value Risk）**：用户真的想用它吗？能解决真痛点吗？
2. **可用性风险（Usability Risk）**：用户第一次打开知道怎么用吗？
3. **可行性风险（Feasibility Risk）**：现有的技术方案能实现吗？
4. **商业生存风险（Viability Risk）**：是否破坏了现有生态或合规边界？

SBC 的核心使命，是在写代码的第一秒进行**风险拦截**：
> **“最大的浪费，莫过于用极高的效率造出了一个根本不该存在的东西。”**

AI 最大的危险就在于其极高的生成效率掩盖了背后的价值虚无。通过强制用户回答核心使用场景与真实意图，直接在萌芽期扼杀伪需求。

## 3. Amazon: Working Backwards（逆向工作法）

亚马逊的创新流程举世闻名：任何内部项目在写第一行代码之前，团队必须先撰写一份面向外部客户的 **新闻稿（Press Release）** 与 **常见问答（FAQ）**。

SBC 将这一流程轻量化为 **“逆向产品宣言”**：
- **第一句话**：用人话说清楚这是给谁用的。
- **第二句话**：它终结了过去什么糟糕痛苦的体验。
- **第三句话**：它最终以什么清晰优雅的形态呈现。

如果 AI 和开发者无法在 3 句话内向一个外行解释清楚这个产品的核心价值，那么这个需求就不配进入编码阶段。

---

## 4. 乔布斯的“产品减法”：Anti-Scope（反向范围）

> **"Deciding what not to do is as important as deciding what to do."**

绝大多数烂项目不是因为功能太少而失败，而是因为第一版被塞满了各种各样“假想可能会有用”的附属特性。

SBC 强制执行 **Anti-Scope 铁律**：
- 每一份合格的 Spec 必须包含明确的 `No-Gos` 清单。
- 砍掉一切对核心价值闭环没有直接贡献的功能。
- 只有敢于对伪需求说“不”，才能在单次 AI 交互中一次性交付高可用、零缺陷的优雅代码。
